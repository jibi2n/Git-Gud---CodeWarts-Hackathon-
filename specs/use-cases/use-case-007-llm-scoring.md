# Use Case 007 — LLM-Based Scoring (Demo)

## User Story

As a user reviewing my skills, I want the readiness score and suggested job archetypes to be generated by an LLM so the demo output feels realistic even when rule-based scoring is incomplete.

## Context

- This is a demo-oriented change to the ML service `/score` endpoint.
- The web app must continue to call `POST /api/score` with the existing request/response shape.
- OpenAI credentials must remain server-side only.

## Intended Behavior

- When `OPENAI_API_KEY` is configured on the ML service:
  - `POST /score` uses an LLM to generate:
    - `readiness.score` (0–100)
    - `readiness.reasoning`
    - `matched_competencies` and `missing_competencies`
    - `job_suggestions` (2–4 items)
  - Output must match the existing response model.
- When `OPENAI_API_KEY` is not configured:
  - `/score` falls back to the existing deterministic scorer (`PathwayScorer.generate_score_report`).

## Acceptance Criteria

- Existing frontend flow remains unchanged (no breaking API changes).
- No OpenAI key is exposed to the frontend.
- `/score` returns valid JSON conforming to the existing `ScoreResponse` model in both modes.
- Errors from the LLM path degrade gracefully to the deterministic scorer.

## Out of Scope

- Replacing `/extract` with an LLM implementation (handled elsewhere).
- Adding new external providers beyond what is already allowed.
